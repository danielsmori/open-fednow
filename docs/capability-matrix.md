# Capability and evidence matrix

Updated September 29, 2026 after [PR #87](https://github.com/danielsmori/open-fednow/pull/87) merged into `main`. OpenFedNow is a synthetic reference implementation. The [release evaluation](reliability/evaluation-report.md) records exact tested source, schedules, failures and exclusions. Author-built tests are engineering evidence, not independent examination or live-rail/vendor certification.

| Area | Implemented and tested locally | Boundary or unfinished work |
|---|---|---|
| SQL reliability service | `/reference/v1/payments` uses scoped SQL ownership, payload conflicts, holds, possible-send intent, synthetic inquiry and final effects. The common external oracle passed on sync and async core fixtures; additional Java cases tested faults, restart, aging and two-JVM leases. | Synthetic accounts and rail only. No authenticated FedNow status, real institution core, all-channel reservation or production timing claim. |
| Existing FedNow send entry | With `openfednow.reliability.legacy-entry-bridge-enabled=true` outside `prod`, `/fednow/send` delegates to the same SQL service; the common external oracle passed. The old Redis/SQL route is disabled by default. | Bridge is an opt-in synthetic evaluation mode. It does not call a vendor adapter or establish a live FedNow mapping. |
| Legacy outbound uncertainty | A missing response retains the legacy debit, records `OUTCOME_UNKNOWN` and prevents automatic replay or compensation. WireMock and database tests cover this quarantine. | No authoritative inquiry or verified resolution action on the legacy saga. The separate SQL path does not migrate old obligations. |
| RTP outbound | XML parsing/serialization and client utilities have local tests. `/rtp/send` returns 503 without submitting. | No outbound financial-control parity, live TCH network connection or certification. |
| Inbound routing and downtime | FedNow/RTP inbound reference routes, source-rail tracking, optional screening, Redis Shadow Ledger and queue/reconciliation fixtures have tests. Downtime sends are disabled by default. | Synthetic ACSP-shaped responses, Redis/SQL split writes and cached balances do not prove service-status validity or cross-channel funds availability. |
| FIS, Fiserv and Jack Henry adapters | Vendor-shaped WireMock tests exercise JSON/SOAP request construction, authentication and response mapping. A common v1 capability gate reports fixture-only evidence. | No vendor-environment verification, enforceable reservation/expiry, posting deduplication, reversal identity or lost-acknowledgment lookup. See the [adapter matrix](reliability/adapter-capabilities-v1.md). |
| Evaluation package | The same eight-case external scenario oracle passed on Java sync, Java async, the guarded gateway bridge and a separate Python/SQLite target; six isolated negative controls detected their intended assertions. | All targets and faults were author-built. Partial S01–S18 coverage and deterministic schedules are detailed in the [scenario register](reliability/requirements.csv). |

The September 23 [controls evaluation](evaluation.md) and September 28 [candidate evidence](reliability/evidence/candidate-2026-09-28/README.md) remain historical snapshots. The September 29 [bundle](reliability/evidence/candidate-2026-09-29/README.md) is the final executable-source evaluation for PR #87. Its source SHA differs from the squash commit on `main`; the bundle records both source and raw observations.
