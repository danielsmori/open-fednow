# Fiserv Banking Hub integration discovery

Reviewed 2026-11-05 against public Fiserv Developer Studio pages. This is a discovery and local contract deliverable, not a provider-tested integration.

## Identified public environment

- Product: Banking Hub, Premier API family, with `Premier-Immediate` on **Add Transfer** and `Premier-DDA` on **Get Account Details**. Other core options and product compatibility were not evaluated.
- The [getting-started guide](https://developer.fiserv.com/product/BankingHub/docs/get-started.md) describes a trial workspace for a **shared Premier Sandbox Environment**. It separately describes a paid Banking Hub Connection plan for a dedicated test environment and additional services. Daniel created a Trial workspace on 2026-11-05. Its supplied host URL is `https://bankinghub-cert.fiservapis.com/banking/efx/v1`. No test account, provider response, or paid plan has been obtained for this project.
- The guide describes token acquisition at `POST https://bankinghub-cert.fiservapis.com/fts-apim/oauth2/v2`, using the workspace API key and secret as **Basic** credentials and a form body of `grant_type=client_credentials`. It says a workspace provides an organization ID and host URL. The opt-in [Trial preflight](../../scripts/fiserv_trial_preflight.py) executed that token request successfully on 2026-11-05. It did not verify required transaction headers, scopes, signing, tenant setup or any core operation.
- The public [Add Transfer reference](https://developer.fiserv.com/product/BankingHub/api/post/xferservice/payments/transfers?branch=main&version=Premier&core=Premier-Immediate) documents `POST /xferservice/payments/transfers`, a required `EFXHeader`, `XferInfo`, and a transfer amount. It describes immediate memo posting, nightly batch entries, and a batch update if memo posting fails. This is **not** evidence of a durable available-funds reservation, posting that consumes a hold, or rail-settlement coordination. A correlation field is not an idempotency guarantee.
- The public Premier [Add Account Hold](https://developer.fiserv.com/product/BankingHub/api/post/acctholdservice/stophold/accountHolds?branch=active&version=Premier&core=Premier) reference describes a hold restriction, amount, reason and expiry. [Get Account Hold](https://developer.fiserv.com/product/BankingHub/api/post/acctholdservice/stophold/accountHolds/secured?branch=active&version=Premier&core=Premier) can retrieve a list or a specific hold by provider hold identifier. Neither public description establishes atomic sufficient-funds checking, client-key lookup after a lost creation response, or safe hold-consuming posting.
- The [Premier-DDA Get Account Details](https://developer.fiserv.com/product/BankingHub/api/post/acctservice/acctmgmt/accounts/secured?branch=main&version=Premier&core=Premier-DDA) reference documents an account selector and a response containing `AcctRec.DepositAcctInfo.AcctBal` entries. The appropriate available-balance type, freshness, fixture account, and trial behavior are not yet verified.
- The legacy `FiservAdapter`/`fiserv/` code uses `/banking/v1/*` paths, form-body client credentials, and fixed-point cent strings. Those are local fixture shapes. They have not been mapped to this Banking Hub contract and must not be aimed at a Fiserv host.

## Access and safety boundary

The user has created a Banking Hub Trial workspace and configured credentials in a private local file. Token acquisition was tested, but no Fiserv-approved synthetic account fixture has been identified. Do not buy a plan or invoke money-changing APIs as part of local checks. The existing `/fednow/send` walkthrough uses a synthetic SQL core and separate rail simulator. It does not use Banking Hub. The new outbound core contract defaults to unsupported and cannot authorize a send.

A future provider test needs official versioned schemas for the chosen operations, approved synthetic account IDs, permitted test behavior, and credentials stored outside Git. A local private configuration template is at `~/.config/openfednow/fiserv-trial.env` on Daniel's machine; it is not part of this repository. Confirm any commercial terms directly before selecting a plan. Capture redacted provider observations and a separate lookup before claiming a financial effect.

The tracked [configuration example](fiserv-trial.env.example) contains placeholders only. The local file should be readable only by its owner (`chmod 600 ~/.config/openfednow/fiserv-trial.env`). Fill its API key, secret and Premier organization ID from the Trial workspace without sharing them in chat, screenshots or issue comments. Leave account fields blank until Fiserv documents or provides an approved synthetic DDA fixture. Run `python3 scripts/fiserv_trial_preflight.py` for a local readiness check or add `--authenticate` for one token request. The preflight refuses destinations other than the documented CERT host and never prints the token or credentials. It makes no account or money-changing request.
