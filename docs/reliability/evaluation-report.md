## Results and boundaries

A fresh detached checkout at the tested SHA and a new Compose project were used. With Homebrew JDK 17.0.20.1, Maven 3.9.16, Python 3.9.6 and Docker Engine 29.7.2 on macOS 27/Apple Silicon, the full default suite passed **618/618** and the full Testcontainers integration suite passed **207/207** (zero failures, errors and skips). The evaluator's selected control, vendor-shaped adapter and integration suites passed **48/48**, **38/38** and **64/64**. Six isolated negative controls failed exactly their intended named assertions, with no build or harness failure counted as detection.

The unchanged eight-case common manifest passed **8/8 in each of four configurations**: Java synchronous SQL core, Java asynchronous core acknowledgment, the controlled `/fednow/send` bridge, and a separate Python/SQLite reference target. The external oracle compared operation identity, HOLD/POST/RELEASE rows, account ledger and held balances, and independently recorded rail status/submission counts. S07 now covers changed amount, changed payee and the same business key in two institution scopes. S16 races two distinct 70,000-minor-unit payments against 100,000 available units: one succeeds with one HOLD and POST, while the other is refused before a remote effect. These are deterministic schedules, not a probability or load study.

The Java-only edge runner passed **11/11** cases: empty, malformed, failed and uncorrelated submission replies; the same four inquiry outcomes; aged unresolved escalation; unavailable synthetic core refusal; and delayed asynchronous core acknowledgment/recovery. For non-final outcomes, the archived traces show retained holds and no fabricated rejection or final financial effect. S11 used **two separate JVMs** sharing PostgreSQL: one claimed the inquiry, a second was refused, the lease expired, the second claimed it, and the first worker's stale result was fenced before one settlement POST. S05 killed the JVM after the independent simulator recorded a remote effect and before local outcome persistence; restart retained the hold, did not resubmit, and reconciled through inquiry. The aged INVESTIGATION state and hold also survived the restart. Each process-kill and lease experiment used one declared schedule.

The synthetic `/reference/v1/payments` path and the explicitly enabled non-production `/fednow/send` bridge share `ReliablePaymentService`, SQL ownership, fingerprint conflicts, holds, possible-send intent, inquiry and final effects. The default legacy Redis/SQL route remains disabled, as does the return route. The three existing vendor-shaped adapters were tested against local WireMock serialization/response fixtures and the common capability gate. Their balance and posting interfaces are **not** verified all-channel reservations, posting deduplication, reversal, or lost-acknowledgment lookup; the bridge does not call them. [The adapter matrix](adapter-capabilities-v1.md) states each limit.

The fresh checkout's `docker compose up -d` command took **0.26 s** with images already cached; a later `up -d --wait` readiness command took **0.62 s** after the containers had started. These are separate command timings, not a cold-download setup benchmark. The full unit run took **15.22 s**, full integration run **41.01 s**, and the complete evaluator **196.27 s**. Within the external run, process setup to target health took **4.77 s** and the external orchestration took **113.65 s**. One post-start Java RSS sample was **712,304 KiB**. Container memory samples after the run were PostgreSQL 28.3 MiB, Redis 9.594 MiB and RabbitMQ 148.3 MiB. None is a peak, throughput, or bank-capacity measurement. ## Exclusions and interpretation

[The scenario register](requirements.csv) identifies coverage per S01–S18. S08 and S10 remain primarily Java integration tests; S09 covers pre-send recovery and one post-effect crash, not every possible boundary. S13 has only rollback/retry and unknown-return checks; a durable return operation is not in this release. The reference slice publishes no broker event and claims no transactional outbox. No independent third-party target, randomized schedule population, peak resource measurement, real institution core, or authenticated live status was available. Restricted FedNow message/transport/security and vendor specifications were unavailable, so the synthetic 30-second inquiry wait, 15-second lease and 24-hour escalation are engineering fixture values, not rail timing rules. The public FedNow Operating Procedures v3.6 informed the settlement/posting distinction; live eligibility and the adjacent cycle-day/calendar-day inquiry interpretation remain unresolved.

Compared with the original clean baseline `c7e5acb`, the known lost-confirmation example had fabricated rejection and compensation after a synthetic timeout. Main's #82 already quarantines that legacy uncertainty; the proposed branch adds SQL-authoritative scoped ownership, a shared guarded gateway bridge, independent effect oracles and cross-process recovery tests. The baseline used mocks and a different oracle, so no numerical reliability improvement, cost saving, institution demand or national impact is inferred. Daniel's personal design/review contributions must be substantiated separately from this AI-assisted implementation.
