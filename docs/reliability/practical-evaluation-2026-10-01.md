## Reproduction record

The evaluator used macOS 27 on Apple Silicon, Docker Engine 29.7.2, Homebrew JDK 17.0.20.1, Maven 3.9.16 and Python 3.9.6; [environment.json](evidence/practical-2026-10-01/final-full/environment.json) records the exact commands and clean source. The host's default Java was 27, so `JAVA_HOME` was explicitly set to JDK 17. Docker images and Maven dependencies were already cached. The first `docker compose -p openfednow-practical-20261001 up -d postgres redis rabbitmq` attempt failed before test execution because this repository fixes container names already held by stopped older containers. No prior container was removed. A temporary [Compose override](evidence/practical-2026-10-01/compose.override.yml) assigned unique names, and `docker compose -f docker-compose.yml -f /tmp/openfednow-practical-compose.yml -p openfednow-practical-20261001 up -d --wait postgres redis rabbitmq` reached healthy dependencies in 10.63 seconds. This is **cached setup**, not a cold download measurement. The manual interventions were setting JDK 17 and supplying the name override. A true first-download setup time was unavailable and is not estimated.

From the clean source checkout, the exact complete command was `python3 scripts/evaluate.py --integration --negative-control --external` with `JAVA_HOME` set as above. The full run took 199.88 seconds wall time. Separate commands `mvn -B --no-transfer-progress test` and `mvn -B --no-transfer-progress -Dgroups=integration -DexcludedGroups= test` took 12.36 and 41.79 seconds wall time. The external harness in the complete run took 114.02 seconds, including 5.18 seconds target startup to health; these are nested measurements, not additive. One Java RSS sample was recorded, not peak memory or throughput. Two more final-source external runs passed in 116.83 and 114.75 seconds. Their local simulator databases were reset between runs; Java SQL state used new unique identifiers. Earlier October-main runs took 210.86 seconds for the full evaluator and 114.71 seconds for an external repeat. All attempts and failures are recorded; the [bundle README](evidence/practical-2026-10-01/README.md) separates runs by source.

The same development agent changed the harness and evaluated it. No independent reviewer or external institution ran these scenarios. Driver adaptation effort for an outside target was not measured; no estimate is presented as an observation. The provided Python target is a reproducible portability control, while CI on GitHub is only an additional environment check if it passes on this PR.

## Boundaries and unresolved dependencies

`/reference/v1/payments` uses synthetic SQL balances and status inquiry. The guarded `/fednow/send` bridge is enabled only for non-production evaluation and shares that service. Default legacy outbound and `/fednow/return` remain disabled; vendor-shaped FIS, Fiserv and Jack Henry adapters have local fixtures but no verified compatibility or shared, all-channel core reservation. A simulator's `SETTLED` status is separate from local `POST`; neither represents an authenticated live outcome. The bridge does not establish institution certification, fraud prevention, cost savings, commercial uptake or national impact. [Adjacent official, commercial and open-source resources](alternatives.md) are compared only from their current first-party public descriptions.

Restricted FedNow message, transport, security and test-access specifications; institution-specific core reservation and posting guarantees; real vendor contracts; live status authority and inquiry timing; and independent engineering review remain external dependencies.
