# Baseline and known-defect reproduction

Historical baseline source: `c7e5acb6142d180b756a67afd92e3cf5291d99a1` (`origin/main` as inspected September 28, 2026). The detached baseline worktree was clean. At that time, PR #82 (`601aeda`, uncertainty quarantine) and its stacked PR #83 (`17606d7`, evaluation and negative control) were open. PR #82 later merged into main; #83–#86 merged into development branches. The consolidated release candidate is proposed against main in [PR #87](https://github.com/danielsmori/open-fednow/pull/87); see the [current evaluation report](evaluation-report.md).

Command: `mvn -B test -Dtest=UncertainSubmissionReproducerTest --no-transfer-progress` in the clean baseline worktree. Maven 3.9.16 used Homebrew Java 27 on macOS 27 / Apple Silicon; Docker Engine 29.7.2 was available. Result: one test passed. The synthetic HTTP server received the payment before delaying its reply; the client timed out and the router logged a synthetic `RJCT/NARR` and compensation. The test passes because it *characterizes* that unsafe behavior, not because the invariant holds. Its mocked financial services do not prove a real balance movement or settlement. Exact balance/event assertions require the later external oracle. A later JDK 17 run should be recorded separately rather than silently substituted.

The corrected PR #83 evaluation command `python3 scripts/evaluate.py --integration --negative-control` passed its selected 48 control and 47 integration tests. Two isolated negative controls each failed one expected assertion (screening and unknown-to-rejection). These runs are on `17606d7`, not on the baseline and not proof of all scenarios in the plan.

Known baseline failure: remote acceptance followed by a lost response is treated as rejection, so a local release can occur while the remote effect remains. Gaps identified in the historical #83 snapshot included a read-then-create idempotency race, Redis/SQL split financial effects, no authoritative inquiry or actor-audited resolution, and no shared core reservation guarantee. The current [scenario register](requirements.csv) records the release candidate's tested coverage and remaining limits.
