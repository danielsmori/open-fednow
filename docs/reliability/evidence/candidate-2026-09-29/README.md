# Synthetic reliability release-candidate evidence, 2026-09-29

This bundle records the clean-checkout evaluation of executable source `98f1613295516b80fa2efbceb95510587df379bd` for [PR #87](https://github.com/danielsmori/open-fednow/pull/87). The tested checkout was clean (`environment.json`). This evidence and the final public-doc edits were committed later, without executable changes. PR #87 targets `main`; the release candidate was not on `main` when these results were recorded. The [report](../../evaluation-report.md) interprets the results; [scenario coverage](../../requirements.csv), [adapter capabilities](../../adapter-capabilities-v1.md), [architecture](../../architecture.md), and [reproduction instructions](../../reproduce.md) are part of the proposed repository change. The September 28 evidence directory is a historical candidate, not the final-source result.

`source-snapshot.zip` contains the exact tested source tree, and `source-manifest.json` records SHA-256 for every archived source file. `SHA256SUMS` verifies the files in this bundle; from this directory run `shasum -a 256 -c SHA256SUMS`. The source ZIP predates the final report and this README, so its own documentation describes the earlier candidate. It is the correct archive for reproducing the tested executable files.

The runner command was `python3 scripts/evaluate.py --integration --negative-control --external`. `results.json`, `external-results.json`, `openfednow-*.json`, `reference.json`, `edge-cases.json`, `two-worker-s11.json`, and `restart-s05.json` hold structured outcomes and observed local/remote effects. Their corresponding `.log` files are raw output. JUnit XML appears in the named subdirectories. `full-unit.log`, `full-integration.log`, `full-test-timing.json` and `evaluator-timing.json` document the fresh full suites and elapsed runs. `initial-failed-unit.log` preserves the initial migration-count assertion failure on precursor `3661b12`, fixed in the tested source.

`fresh-setup.json` records setup commands and timing; `environment.json`, `container-images.json`, and `container-stats.jsonl` record available version and resource observations. Local paths under `/tmp` in timing JSON identify where the raw logs were first written; copies are stored here under the corresponding filenames. Images were cached, and the memory figures are samples, not peaks. `ci-records.json` captures the green unit and integration jobs for the tested executable revision. Any later CI run at the documentation-only PR head must be checked separately.

All targets, payment identities, balances, and rail responses here are synthetic. The Python target is an author-built reference fixture. Neither it nor the vendor-shaped WireMock tests establish live FedNow, bank-core, or vendor interoperability. The four configurations use the same external oracle, while the Java-only edge, two-process, and restart cases cover additional declared schedules. The controlled gateway bridge is non-production and opt-in; existing vendor adapters are assessed but are not connected to the SQL reliability service.
